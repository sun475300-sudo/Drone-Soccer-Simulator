> 2026-10-28 현재 우선순위: **한국어 첫 비행 단계 안내·작은 화면 가독성 → 입력·설정 저장 안전 → 최신 통합본 회귀 → AI 난이도 비교**. 이미 구현한 조종기 기능과 별도 Topgun 작업을 보존한다. [사용자 20개 작업의 현재 구분](#remaining-priorities)과 아래 A~J의 전체 범위를 함께 유지한다.

2026-10-29 v0.7.14-rc1 후보의 새 빌드·설치·실제 창 검증과 미검증 범위는 [릴리스 검증](releases/v0.7.14-rc1.md)을 따릅니다. 공개 여부는 릴리스 페이지에서 확인합니다. 아래 상태는 2026-10-28 당시 기록입니다.

작성:2026-10-27, 당시 대조:**2026-10-28**. 당시 공개본은 **v0.7.13-rc1 R3(C7)**이며 5개 자산의 익명 다운로드·해시를 확인했다. **후속 로컬0ea9a3 R2는 미배포**다. [공개 후 검사·차단](post-release-review-2026-10-28.md)을 함께 확인한다. 과거 v0.7.4~v0.7.10 및 별도 로컬 AIUI1 기록은 해당 이력으로 보존한다. 최종 입력 지문·패키지·검사·공개 상태는 [v0.7.13-rc1 검증 기록](verification.md#v0713-rc1)을 기준으로 확인한다.

**현재 구현과 검증 대기를 구별한다.**

후속 로컬 **0.7.14-dev-ui1 /0350e848·169입력**에서 HUD/장치명과 C++ AI 기록 비교 UI를 구현·빌드·검증했다. [최신 결과와 실패 이력](product-ui-2026-10-28.md)을 따른다. 아래 공개C7·0ea/CLI699 이력의 검사 수를 새 지문에 합산하지 않는다.

- 새 첫 비행은 **이륙 → 호버 → 이동 → 착륙 → 첫 득점 → 마지막 착륙**의 6단계 관측 안내다. 조건 충족 뒤 사용자가 다음을 선택하며 자동 ARM·조종·단계 전환은 하지 않는다. 착륙 뒤 다음/최종 완료 때 현재 착륙·DISARM·최저 스로틀·키 중립을 다시 확인한다. 첫 득점만으로 마지막 착륙이 완료된 것으로 표시하지 않는다.
- 순수 상태 검사 **190개 통과**는 합성 관측값의 근거다. 중간 d70fe 지문의 native42개는 예비 이력으로 보존하며 R3 합계에 넣지 않는다. R3의 첫 비행·AI 이동 native292개와 실제 Windows 입력 검사를 확인했다. 후속 로컬0ea에서는 실제 OS 키보드/마우스 자동 조종으로6단계 연속 완주1회·득점1:0·최종 착륙/DISARM을 확인했다. **사람의6단계 수동 비행·초보자 독립 사용성·실물 조종기·다른 PC는 여전히 미검증**이다. 관측 수치를 공식 실력 평가나 실기체 합격 기준으로 인증하지 않는다.
- 별도 `0.7.12-local-aiui1`의 AI 설정/결과 한국어81개·720p 화면·저장/대전/입력 검사326개는 그 빌드 지문 `62635a4bc471d234990e56b9fc2b88e1382878594c851bba034868567b29faa6`의 기록이다. 새 통합본에도 같은 결과가 난다고 가정하지 않는다. 이전 guide1의 사용자 직접 확인 안내와 새 관측형 안내도 별도 구현·증거로 유지한다.
- 실물 조종기는 학교에 있어 스틱·아밍 스위치·USB 손실/재연결과 다른 물리 PC 검사는 **미검증**이다. 같은 PC의 새 폴더·격리 데이터·합성 입력으로 대체 완료하지 않는다.
- 과거의 커밋·푸시·PR·배포 보류 지시는 이력으로 보존한다. **최신 요청은 검증 후 기존 공개본을 덮어쓰지 않는 새 사전 배포판 준비를 허용**한다. 실제 공개 전 최종 소스·패키지·재배치 검사·문서와 제한 사항을 대조한다. 이 계획서 편집 자체로 공개하거나 검증을 승인 처리하지 않는다.

현재 우선 작업 이후의 순서는 조종기 현장 검수·AI 연습/대전 → 탑건 로컬 기록전 → LOS·언어·UI → 경기 연출·중력 → 정밀 물리·경기 운영 → LAN·온라인 → 통합 배포 검수다. 입력 손실·오득점·기록 손상처럼 확인된 결함은 먼저 수정한다. 연결 없이 가능한 개발은 현장 검사 대기와 별도로 진행한다.

[탑건 국가별·세계 통합 순위](follow-up-plan-2026-10-28.md#country-world-leaderboards)와 [다국어 확장](follow-up-plan-2026-10-28.md#internationalization)은 **요구·설계 초안 문서화 완료, 기능 구현·서버 운영·추가 언어 검수 미완료**다. [28개 분야·326개 명세](simulator-feature-plan.md), 기존16개 후보와 A~J의 미완료 요구를 축소하지 않는다.

## 사용자 미완료 목록과 현재 구분 — 2026-10-28 (2026-10-31 갱신)

## 1. 제품 목표와 유지할 기준

Windows Unreal Engine 기반으로 실제 드론축구의 **경기장 밖 LOS 조종**, 개인 연습, 팀 경기,

**조종기 설정**이라는 공통 용어를 사용한다. RadioMaster Boxer는 실제 시험 기종 중 하나다.

## 4. 조종기 설정 완성

첫 사용자 흐름은 **장치 연결 → 실제 장치 선택 → 스틱 배치 선택 → 축 학습 → 범위/중립/방향 확인 →
검토 후 저장 → 최저 스로틀에서 입력 활성화 → 별도 ARM**으로 고정한다. 자동 감지 결과를 사용자가
검토하지 않은 채 바로 비행에 사용하지 않는다. 한 단계 실패가 전체 설정 초기화로 이어지지 않게 한다.

| 과제 | 작업 | 통과 조건 |
|---|---|---|
| Mode1/2 | 그림·손 위치·안내·방향 확인을 선택 모드에 맞춤 | Mode1은 오른쪽 수직 스로틀, Mode2는 왼쪽 수직 스로틀. 모드 선택만으로 저장 축을 바꾸지 않음 |
| 레이트/Expo | 기존30~360deg/s·Expo0~80%와 곡선/미리 보기 유지 | 끝값/중립·단조성·ANGLE 한도·실제 회전 명령·저장/취소 검사 |
| 아밍 | 기존 토글/2단 스위치·버튼 학습의 실물 시험 | 누른 채 시작/재연결, 높은 스로틀, 메뉴 복귀에서 예기치 않은 ARM이0회 |

## 6. 탑건 이벤트와 기록방

사용자 확정 요구는 **기둥2개 S자 코스·기록 경신·닉네임/ID/국적**이다. 아래의 최단 시간 방식과
충돌 처리·회차는 개발 초안이며 공식 드론축구 규칙이 아니다. 코스와 규칙에는 별도 버전을 붙인다.

### 6.1 코스·판정 초안

1. 경기장과 분리된 연습 코스에 기둥2개, 출발/결승선, 방향 안내·필수 통과 구역을 배치한다.
2. 출발 → 첫 기둥 한쪽 → 두 기둥 사이 → 두 번째 기둥 반대쪽 → 결승의 순서를 검사한다.
3. 초안은1회 완주 최단 시간이다. 역주행·통과 구역 생략·초기화·기체 교체·물리 설정 변경은 기록 무효다.
4. 충돌은 연습에서 계속 날 수 있도록 하되, 초기 공식 기록 범위는 무충돌 완주로 제한하는 안을 시험한다.
   시간 벌점 방식·여러 바퀴·기체 수는 결과를 보고 별도 확정한다.
5. 완주 후 자신의 이전 최고 기록·현재 방 최고 기록·차이를 표시하고, 같은 코스로 재도전한다.

빠른 통과는 프레임의 이전/현재 위치 사이 구간을 검사해 빠뜨리지 않고, 보호구 전체의 여유와
방향·순서를 확인한다. 화면에 표시된 시간만 읽어 점수를 만들지 않는다. 로컬 초안은 정상 배속에서
단조 증가 시계와 통과 시각을 기록하고, 일시정지·물리 시간 누락·비정상 배속이 있으면 기록 자격을
해제한다. 온라인 기록의 최종 시각·판정은 서버가 결정한다.

### 6.2 프로필·기록 데이터

| 항목 | 저장·표시 방침 |
|---|---|
| 닉네임 | 사용자가 입력. 중복 이름 허용 여부를 화면에 설명하고 ID로 구분 |
| 사용자 ID | 로컬은 임의 UUID. 온라인 계정 ID와 구분하며 닉네임 변경으로 새 선수처럼 집계하지 않음 |
| 국적 | 사용자가 국가 코드/표시명을 선택, 미지정 허용. 자동 추정하지 않음 |
| 실행 ID | 각 시도별 별도 ID, 시작/완주/무효 사유·구간별 시간·충돌 사건 |
| 비교 조건 | 코스/규칙/기체/물리/중력/보조 설정 버전과 게임 빌드 기록 |
| 입력 취향 | Mode·레이트·Expo도 기록하되 단순 입력 취향만으로 순위표를 불필요하게 쪼개지 않음 |
| 저장 실패 | 이전 최고 기록 보존·재시도 안내. 손상 파일·중복 등록·중간 종료 검수 |

### 6.3 기록방의 개발 단계

| 단계 | 제공 범위 | 완료 조건 |
|---|---|---|
| 로컬 개인/행사 기록판 | 한 PC의 여러 프로필, 코스별 최고 기록·재시도·내보내기 | 재실행 보존, 동명이인 구별, 다른 조건 기록 분리, 손상/잠금 복구 |
| LAN 기록방 | 같은 네트워크에서 방 개설·참가·동일 규칙 배포·방 최고 기록 | 실제 서로 다른2대 이상 PC의 등록/갱신 일치·중복 사건 거부 |
| 온라인 기록방 | 원격 참가·방 ID·접근 권한·서버 판정·기록 보존 | 다른 회선 시험, 재접속·변조/재전송·잘못된 조건 거부, 동률 처리 일치 |

로컬 JSON 파일을 편집해 만든 기록을 검증된 온라인 기록으로 받아들이지 않는다. 서버 검증 전에는
기록을 로컬/미검증으로 표시한다. LAN·온라인 인프라 방식과 운영 비용은 작은 접속 시험 이후 결정한다.

경기와 비교 가능한 탑건 기록은 정한 물리 프로필을 고정하며 임의 변경 시 별도 연습 기록으로 분리한다.
규칙·점수에 관한 신규 수정은 기존101개 조건뿐 아니라 실제 골대 통과와 변경한 경계 사례를 다시 검사한다.

## 10. 다중 입력·LAN·온라인·리플레이·진단

먼저 같은 PC의2대 조종기를 분리해 소유권·보정창·포커스·입력 손실을 검사한다. 이후 실제 다른
PC의 LAN 연결, 화면 없는 서버, 원격 비공개 방, 공개 방 탐색 순서로 확장한다. 서버가 기체 소유권·
득점·시간·기권·재접속 상태를 최종 결정하며 클라이언트의 화면 시간/좌표를 그대로 신뢰하지 않는다.

시험 조건 초안은 RTT50/100/150ms·패킷 손실1/3/5%다. 실제 측정 RTT와 주입 조건을 함께 기록하고,
같은 시각의 득점·종료·충돌·접속 해제 결과가 참가자 모두에게 일치하는지 검사한다. 서버 장애·
호스트 이탈은 중단/무효/복구를 명시하며 재접속이 자동 ARM을 허용하지 않게 한다.

리플레이는 실제 사건·상태 기록과 시각 재생부터 시작한다. 고스트는 충돌·득점에 참여하지 않고,
재시뮬레이션이 원본 Chaos와 완전히 같은 결과를 낸다고 가정하지 않는다. 기록에는 빌드·설정·단위·
누락 구간을 남기고, 서버 확정 사건과 임시 후보를 구분한다.

기존 F5 CSV·F6 JSONL을 바탕으로 문제 순간 표시, 선택적 순환 기록, 사용자 메모, 로컬 진단 ZIP을
추가한다. 저장 실패가 조종을 멈추게 하지 않으며, 공유 전에 포함 파일을 확인하게 한다. 개인 보정·
전체 PC 경로·장치 고유값·비밀값은 공개 자료에서 제외한다. 외부 자동 전송은 이 계획의 기본 기능이 아니다.

기록하고, 다른 엔진 버전 지원은 별도 검사한다. 실물 입력에는 충전된 조종기·데이터 케이블·실제 스틱을
움직일 시험자가 필요하다. 사용성/난이도는 초보 사용자와 숙련 조종자/코치의 평가를 나누어 받는다.
다른 PC·LAN/원격 단계에는 실제 복수 컴퓨터와 네트워크 환경을 확보한다. 서버 방식·운영 비용은
H/I 착수 시 사용 규모와 접속 시험 결과로 산정하며, 현재 계획서에 근거 없는 기간·비용을 확정하지 않는다.

## 13. 공통 검사와 출시 기준

| 검사 층 | 확인할 내용 | 남길 근거 |
|---|---|---|
| 독립 계산 | 입력 곡선·포화·득점 경계·코스 순서·저장 스키마 | 정답값·실패 입력·검사 결과 |
| Unreal 실행 | 실제 힘/토크·접촉·시간·UI 상태·세션 전환 | 버전·설정·빌드 지문·로그/상태·측정값 |
| 렌더/화면 조작 | 글꼴·해상도·시점·클릭·포커스·알림 | 같은 조건의 화면과 수행한 조작. 화면 밖 렌더는 실제 마우스 시험과 구분 |
| 실제 조종기 | 스틱/버튼·모드·손실/재연결·연속 비행 | 실제 기종·상태·입력/행동 기록. 합성 입력을 실물 증거로 사용하지 않음 |
| 배포·다른 PC | 새 압축 해제·필수 구성요소·개인 저장·업데이트 | ZIP 해시·경로·PC 환경·실행 결과. 같은 PC 새 폴더와 다른 PC를 구분 |
| 다중 사용자 | 조종권·서버 시간·득점·기록·장애 | 참가자별 동일 사건과 최종 결과, 연결 품질 |

각 작업은 **현상/요구 → 구현 → 독립 확인 → 실제 실행 → 실패 수정 → 필요한 회귀 검사 →
배포본/새 경로 검사 → README/검증 기록 → 커밋·푸시**로 마친다. 문서만 바꾼 경우에는
내용·링크·상태·기능 번호를 검사하며 게임 코드를 새로 빌드한 것처럼 보고하지 않는다.

공개 실행본에는 실제 검증한 코드/콘텐츠 지문·ZIP 해시·지원 환경·알려진 제한·복구 방법이 있어야 한다.
개발 브랜치의 기능이 기존 공개 ZIP에도 있다고 안내하지 않는다. 손실된 보정·의도치 않은 ARM·
잘못된 최종 점수·기록 파일 손상 같은 결함이 있으면 관련 기능 출시를 멈추고 원인을 고친다.
