## 1. 제품 목표와 유지할 기준

Windows Unreal Engine 기반으로 실제 드론축구의 **경기장 밖 LOS 조종**, 개인 연습, 팀 경기,
AI 상대 훈련, 탑건 기록전, 관전·심판 운영을 제공한다. 사용자에게는 특정 제조사 이름 대신
**조종기 설정**이라는 공통 용어를 사용한다. RadioMaster Boxer는 실제 시험 기종 중 하나다.

| 기준 | 제품에 적용할 원칙 |
|---|---|
| 조종 방식 | 고글 없는 LOS가 기본. 파일럿은 자기 팀 경기장 밖에 위치하며 기본 시점을 기체 내부로 바꾸지 않음 |
| 비행 모드 | 모든 수동 기체 ANGLE·최대 목표 기울기35도. Yaw·스로틀은 수동이며 ANGLE을 고도 유지라고 설명하지 않음 |
| 경기 프로필 | 현재 선택한 FIDA Class40 프로필 유지. FAI·20cm급은 별도 규정·물리 프로필로 확장 |
| 경기장·기체 | 현재 프로젝트 기준16×7×4.5m·40cm 보호구·0.9kg 가정 기체·골대 개구60cm·중심높이3.0m. 규정값/선택값/가정값을 구별 |
| 비행 물리 | 실제 힘·토크로 이동. 초기화·명시적 시험 배치를 제외하고 위치를 강제 이동해 AI 성능을 맞추지 않음 |
| 모드 분리 | 공식 규정 기반 수동 경기, AI 연습/변형 대전, 탑건 이벤트의 규칙·기록을 분리 |
| 시작 안전 | 처음 실행·장치 변경·재연결·메뉴 복귀가 자동 ARM으로 이어지지 않음 |
| 다른 PC 사용 | Unreal·Python·Git 설치 없이 전체 ZIP 해제 후 실행. 개인 보정과 기록은 배포 ZIP에 넣지 않음 |
| 시각 품질 | 실사 지향 재질·구조와 LOS 식별성 개선. 제조사 실측 디지털 트윈·공식 인증으로 표시하지 않음 |

규정 수치는 프로젝트에 보관된 [규정 근거](rules-sources-2026.md)의 적용 프로필이다.
대회용 판정을 확정할 때는 해당 판본과 대회 지침을 다시 대조하며, 이 계획서 작성으로 규정 최신성을 새로 인증하지 않는다.

## 2. 현재 상태와 완료의 의미

**소프트웨어 검사 완료**, **부분 구현**, **미구현**, **현장 검사 대기**를 구분한다.
기본 구현이 있다는 이유로 기능 전체를 완료 처리하거나326개 목록의 단순 체크 비율을 제품 완성도로 사용하지 않는다.

## 4. 조종기 설정 완성

첫 사용자 흐름은 **장치 연결 → 실제 장치 선택 → 스틱 배치 선택 → 축 학습 → 범위/중립/방향 확인 →
검토 후 저장 → 최저 스로틀에서 입력 활성화 → 별도 ARM**으로 고정한다. 자동 감지 결과를 사용자가
검토하지 않은 채 바로 비행에 사용하지 않는다. 한 단계 실패가 전체 설정 초기화로 이어지지 않게 한다.

| 과제 | 작업 | 통과 조건 |
|---|---|---|
| Mode1/2 | 그림·손 위치·안내·방향 확인을 선택 모드에 맞춤 | Mode1은 오른쪽 수직 스로틀, Mode2는 왼쪽 수직 스로틀. 모드 선택만으로 저장 축을 바꾸지 않음 |
| 레이트/Expo | 기존30~360deg/s·Expo0~80%와 곡선/미리 보기 유지 | 끝값/중립·단조성·ANGLE 한도·실제 회전 명령·저장/취소 검사 |
| 아밍 | 기존 토글/2단 스위치·버튼 학습의 실물 시험 | 누른 채 시작/재연결, 높은 스로틀, 메뉴 복귀에서 예기치 않은 ARM이0회 |
| 범용 입력 | 입력 취득과 보정/비행 계층 분리, 추가 입력 API 후보를 실제 기기와 비교한 뒤 채택 | 기기별 축/버튼·중립·분리/재연결 결과가 있는 호환표. 미시험 기기는 미시험으로 표시 |
| 장치 식별 | 장치 교체·슬롯 변경·동일 제품2대·동시 연결 검사 | 다른 기기의 보정·아밍키가 자동 적용되지 않음. 식별 불확실하면 재선택 요구 |
| 보조 채널 | 축으로만 전달되는 스위치·3단 스위치 등 추가 배정 설계 | 버튼 지원과 구분. 임계값·히스테리시스·OFF 확인·새 전이의 별도 시험 |
| 장애 복구 | 저장 잠금·손상 파일·권한 문제·USB 손실·포커스 상실 | 이전 설정 보존, 이유/해결 안내, 연결 복구만으로 모터 재가동 금지 |

호환 시험표에는 제조사/모델·펌웨어·USB 모드·입력 경로·축/버튼 수·Mode1/2·OS·게임 버전·결과를 기록한다.
Boxer 한 기종의 성공으로 모든 조이스틱을 지원한다고 판단하지 않는다. 새 입력 경로 도입 시 기존 실물
`RadioProfile.json`을 이관 전에 보존하고, 읽기/변환/취소/복구를 따로 시험한다.

## 5. 싱글플레이 AI 연습과 AI 대전

**1차 목표는 상대 AI 총3대 또는4대**다. 숫자는 기체 수를 뜻하며 기존10대 APF 이동 시연과 다르다.
현재 공식 수동 경기의 자율 금지 조건을 전역으로 해제하지 않고, AI 전용 세션에서만 허용한다.

| 모드 | 플레이 방식 초안 | 평가 |
|---|---|---|
| AI 연습 | 사람이 공격수1대를 조종, AI3/4대가 수비. 배치 고정/무작위·즉시 재시도 | 유효 골·골 시도·충돌·복귀 시간·훈련 지속 시간 |
| AI 대전 | 사용자 팀과 AI 상대 팀의 변형 경기. 상대 총3/4대 중 공격수1대와 나머지 수비를 배정하는 초안 | 양 팀 실제 유효 득점·승패·시간·사건 기록. 사람 팀 구성은 첫 시제품 평가 후 확정 |
| 향후5대5 혼합 | 사람·AI로 두 팀을 구성하고 각 기체의 조종권/역할 구분 | 전원 복귀·공격수 권한·규칙 일치. 1차3/4대 연습 완료와 별도 검수 |

3/4대 변형 대전은 FIDA 정규5대5 완성으로 표시하지 않는다. AI 연습과 대전은 메뉴·결과·기록에서
구분하고, 사용자가 원하지 않은 기체에 조종권을 넘기거나 수동 기체를 자동 ARM하지 않는다.

| 난이도 | 행동 설계 | 조정할 값과 검사 |
|---|---|---|
| 초급 | 느린 반응·넓은 수비 간격·단순한 골대 주변 방어 | 반응 지연·최대 목표 속도·가속도·수비 반경. 초보자가 진입 방향을 식별할 수 있는지 평가 |
| 중급 | 좌우 커버·주기적 위치 교환·공격 경로 차단 | 반응·예측 시간·전략 전환 빈도. 교착/과도한 밀집 여부 측정 |
| 고급 | 협력 차단·역할 교대·복귀 동선 압박 | 같은 물리 한도에서 전략/반응 개선. 미래 입력을 읽거나 순간이동하지 않음 |

시드로 배치·선택 전략을 재현하되 Chaos 궤적이 서로 다른 PC/FPS에서 완전히 같다고 보장하지 않는다.
배치 시 보호구·골대·네트·다른 기체와의 초기 겹침을 거부하고, 진행 중에는 같은 질량·추력·전력·충돌
모델을 사용한다. APF는 이동/회피 계층으로 활용하고 공격·수비 의사결정과 구분한다.

완료 기준은3/4대×3난이도×정의한 시험 시드에서 정상 시작·실제 힘 기반 이동·정상 종료·재시작,
유효 득점/무효 통과, 통신 단절/교착 복구를 확인하는 것이다. 목표 난이도는 코치·사용자 평가와
성공률/충돌/차단 시간 자료로 조정하며 임의의 성공률을 이미 달성했다고 표시하지 않는다.

## 6. 탑건 이벤트와 기록방

사용자 확정 요구는 **기둥2개 S자 코스·기록 경신·닉네임/ID/국적**이다. 아래의 최단 시간 방식과
충돌 처리·회차는 개발 초안이며 공식 드론축구 규칙이 아니다. 코스와 규칙에는 별도 버전을 붙인다.

### 6.1 코스·판정 초안

1. 경기장과 분리된 연습 코스에 기둥2개, 출발/결승선, 방향 안내·필수 통과 구역을 배치한다.
2. 출발 → 첫 기둥 한쪽 → 두 기둥 사이 → 두 번째 기둥 반대쪽 → 결승의 순서를 검사한다.
3. 초안은1회 완주 최단 시간이다. 역주행·통과 구역 생략·초기화·기체 교체·물리 설정 변경은 기록 무효다.
4. 충돌은 연습에서 계속 날 수 있도록 하되, 초기 공식 기록 범위는 무충돌 완주로 제한하는 안을 시험한다.
   시간 벌점 방식·여러 바퀴·기체 수는 결과를 보고 별도 확정한다.
5. 완주 후 자신의 이전 최고 기록·현재 방 최고 기록·차이를 표시하고, 같은 코스로 재도전한다.

빠른 통과는 프레임의 이전/현재 위치 사이 구간을 검사해 빠뜨리지 않고, 보호구 전체의 여유와
방향·순서를 확인한다. 화면에 표시된 시간만 읽어 점수를 만들지 않는다. 로컬 초안은 정상 배속에서
단조 증가 시계와 통과 시각을 기록하고, 일시정지·물리 시간 누락·비정상 배속이 있으면 기록 자격을
해제한다. 온라인 기록의 최종 시각·판정은 서버가 결정한다.

### 6.2 프로필·기록 데이터

| 항목 | 저장·표시 방침 |
|---|---|
| 닉네임 | 사용자가 입력. 중복 이름 허용 여부를 화면에 설명하고 ID로 구분 |
| 사용자 ID | 로컬은 임의 UUID. 온라인 계정 ID와 구분하며 닉네임 변경으로 새 선수처럼 집계하지 않음 |
| 국적 | 사용자가 국가 코드/표시명을 선택, 미지정 허용. 자동 추정하지 않음 |
| 실행 ID | 각 시도별 별도 ID, 시작/완주/무효 사유·구간별 시간·충돌 사건 |
| 비교 조건 | 코스/규칙/기체/물리/중력/보조 설정 버전과 게임 빌드 기록 |
| 입력 취향 | Mode·레이트·Expo도 기록하되 단순 입력 취향만으로 순위표를 불필요하게 쪼개지 않음 |
| 저장 실패 | 이전 최고 기록 보존·재시도 안내. 손상 파일·중복 등록·중간 종료 검수 |

### 6.3 기록방의 개발 단계

| 단계 | 제공 범위 | 완료 조건 |
|---|---|---|
| 로컬 개인/행사 기록판 | 한 PC의 여러 프로필, 코스별 최고 기록·재시도·내보내기 | 재실행 보존, 동명이인 구별, 다른 조건 기록 분리, 손상/잠금 복구 |
| LAN 기록방 | 같은 네트워크에서 방 개설·참가·동일 규칙 배포·방 최고 기록 | 실제 서로 다른2대 이상 PC의 등록/갱신 일치·중복 사건 거부 |

기록을 로컬/미검증으로 표시한다. LAN·온라인 인프라 방식과 운영 비용은 작은 접속 시험 이후 결정한다.

근접 화면에서 검토한다. 장식 메시 변경과 질량/충돌체 변경을 분리하고, 형상/개구부/전체 크기를
다시 검사한다. 20cm 기체는 질량·관성·추력·규정이 다른 별도 확장으로 둔다.

실측 순서는 **호버/추력 → 모터 응답 → 축별 감속 → 자유낙하/반발 → 기체 충돌 → 네트 → 표면 효과 →
후류**다. 각 계수에 단위·측정 장비·조건·오차·가정 여부를 남긴다. 측정 전에는 실험 근사라고 표시한다.

## 10. 다중 입력·LAN·온라인·리플레이·진단

먼저 같은 PC의2대 조종기를 분리해 소유권·보정창·포커스·입력 손실을 검사한다. 이후 실제 다른
PC의 LAN 연결, 화면 없는 서버, 원격 비공개 방, 공개 방 탐색 순서로 확장한다. 서버가 기체 소유권·
득점·시간·기권·재접속 상태를 최종 결정하며 클라이언트의 화면 시간/좌표를 그대로 신뢰하지 않는다.

시험 조건 초안은 RTT50/100/150ms·패킷 손실1/3/5%다. 실제 측정 RTT와 주입 조건을 함께 기록하고,
같은 시각의 득점·종료·충돌·접속 해제 결과가 참가자 모두에게 일치하는지 검사한다. 서버 장애·
호스트 이탈은 중단/무효/복구를 명시하며 재접속이 자동 ARM을 허용하지 않게 한다.

리플레이는 실제 사건·상태 기록과 시각 재생부터 시작한다. 고스트는 충돌·득점에 참여하지 않고,
재시뮬레이션이 원본 Chaos와 완전히 같은 결과를 낸다고 가정하지 않는다. 기록에는 빌드·설정·단위·
누락 구간을 남기고, 서버 확정 사건과 임시 후보를 구분한다.

기존 F5 CSV·F6 JSONL을 바탕으로 문제 순간 표시, 선택적 순환 기록, 사용자 메모, 로컬 진단 ZIP을
추가한다. 저장 실패가 조종을 멈추게 하지 않으며, 공유 전에 포함 파일을 확인하게 한다. 개인 보정·
전체 PC 경로·장치 고유값·비밀값은 공개 자료에서 제외한다. 외부 자동 전송은 이 계획의 기본 기능이 아니다.

## 12. 단계별 산출물·선행 조건·일정 관리

다음은 실행 순서이며 달력상 완료일을 약속하는 일정이 아니다. 각 단계 착수 시 실제 남은 범위·
장치/시험자·빌드 시간·서버 필요성을 확인해 예상 기간을 갱신한다. 하드웨어 대기 항목 때문에
무관한 개발을 중단하지 않지만 해당 현장 검사를 통과 처리하지도 않는다.

| 단계 | 산출물 | 선행 조건·출구 기준 |
|---|---|---|

| B AI | 3/4대 배치·초중고급·연습/대전·결과 | A의 입력 계약 유지. 실제 이동·점수·장애·재시도 검사 |

배포 검사는 J까지 미루지 않고 각 단계에 반복 적용한다. 실제 계수 측정과 기체 자료 확보는 A~E 중에도
진행할 수 있다. 물리·규칙이 변경되면 기존 탑건 기록의 비교 가능성을 재검토하고 버전별로 보존한다.

필요한 환경과 역할도 단계별로 확보한다. 개발 환경은 현재 Windows·UE5.8·C++ 빌드 도구를 기준으로
기록하고, 다른 엔진 버전 지원은 별도 검사한다. 실물 입력에는 충전된 조종기·데이터 케이블·실제 스틱을
움직일 시험자가 필요하다. 사용성/난이도는 초보 사용자와 숙련 조종자/코치의 평가를 나누어 받는다.
다른 PC·LAN/원격 단계에는 실제 복수 컴퓨터와 네트워크 환경을 확보한다. 서버 방식·운영 비용은
H/I 착수 시 사용 규모와 접속 시험 결과로 산정하며, 현재 계획서에 근거 없는 기간·비용을 확정하지 않는다.
