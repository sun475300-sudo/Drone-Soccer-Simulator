# 로컬 AI 훈련 결과 두 개 비교

`Scripts/compare-ai-results.py`는 이미 저장된 AI 결과 JSON 두 개를 읽고
득점·사람 기체의 보호구 접촉·잔여 내구도·AI 착륙 시간 등의 차이를 출력한다.
Python 표준 라이브러리만 사용하며 게임이나 조종기를 실행하지 않는다.
입력 파일을 변경하거나 별도 결과 파일을 자동 저장하지 않는다.

## 현재 제품 UI — 0.7.14-dev-ui1 로컬 검증

게임의 AI 설정/저장 결과에서 저장 기록 비교를 열고 A/B를 직접 선택할 수 있다. C++로 동작하므로 게임에서 Python을 실행하지 않는다. 최종 입력169개0350e848의 빌드·실제720p/960 창 검증과 미검증 범위는 [제품 UI 보고서](product-ui-2026-10-28.md)를 따른다. 현재 공개 v0.7.13에는 포함하지 않았다. 아래163개 CLI 단계는 당시 이력이며 게임 UI 미연결/미빌드 문구도 그 단계의 기록이다.

## CLI 통합 당시 상태 — 2026-10-28,5455423

별도 비교 브랜치의 기준은 `abc7240da51640d67fb75a4ec08849e1bebb6e11`이다.
그 기준의 게임 입력 지문 `0ea9a3fd…79b198c`에서 검증한 native AI 저장 코드와
이 도구의 schema 1/2·모드·기체 목록·조건을 대조한 뒤 세 새 파일만 수동으로 추가했다.
전체 전달 패치로 기존 체크리스트/검증 기록을 덮어쓰지 않았다.

이 기능은 **개발 환경의 읽기 전용 CLI**다. 게임 내 기록 비교 화면이나 Windows 실행 ZIP에
Python 도구가 포함됐다는 뜻이 아니다. `Scripts/*.py`는 게임 입력 지문 계산에 포함되므로
추가 후 입력 수는 **162→163**으로 바뀐다. 이 브랜치는 Unreal을 새로 빌드하지 않았으며,
기존 0ea 실행본의 회귀 결과를 새 163개 지문 실행 검증으로 재사용하지 않는다.

원본 전달본의 Windows CP949 파이프에서 한글/이모지 출력 실패를 재현하고 CLI 프로세스의
stdout/stderr만 UTF-8로 설정했다. 문자열 길이 제한은 native FString과 같은 UTF-16 단위로
계산한다. OS 콘솔 설정을 바꾸지 않는다. JSON 출력은 UTF-8로 읽는다.

합성 정상 기록의 차이 계산 검사와 실제 엔진이 만든 자동 QA 기록의 차단을 구분한다.
현재 확보한 실제 native QA 결과는 `test_session=true`이며 개인 실력 비교에 사용하지 않는다.
사람의 실제 플레이 기록 두 개 비교·게임 UI 연결·다른 PC·실물 입력 검사는 미검증이다.
현재 로컬 Windows 검사에서 **새 비교37개(전달30+추가7)·기존 분석5개**가 통과했다.
두 검사 모두 이 비교 브랜치를 cwd로 실행했으며, 원본 클라우드 검사 수를 더한 것이 아니다.
실제 엔진 자동QA 기록4쌍은 exit2로 차이 계산을 차단했고 F6 JSONL은 exit1로 거부했다.
입력 원문5개의 전후해시는 같았다. 새 개발소스 지문은
`699cb918d030304e8a08914a3ba0f932aaa25e48718c31cacf7241b3a198ceec` /163개다.
이 지문으로 Unreal을 빌드하지 않았다. 기존162개 지문0ea 실행 검증과 구분한다.
구체적인 CLI 종료 코드·검사 수·기록 파일 보존 근거는 이 브랜치의
`Saved/Verification/AICompareIntegration-*` 기록에서 확인한다.

## 사용

개발 환경의 Python 3.9 이상에서 저장소 루트로 이동한 뒤 실행한다.
Windows 실행 ZIP에 이 개발 도구나 시스템 Python이 포함된다는 뜻은 아니다.

```powershell
python Scripts/compare-ai-results.py "C:\기록\이전.json" "C:\기록\이번.json"
```

두 입력은 `Saved/TrainingResults/AI`에 저장된 **서로 다른 시도의 JSON**이다.
기본 사용자 경로는 `%LOCALAPPDATA%/ImperialWingsSimulator/Saved/TrainingResults/AI`다.
F6의 JSONL·F5의 CSV·자동 검사 요약 파일은 이 도구의 입력 형식이 아니다.
시간순 기록을 자동 선택하지 않으며 전달한 첫 파일이 기준, 둘째가 비교 대상이다.

- `reference` / `candidate`: 각각의 세션·기록 조건·지표.
- `deltas`: **둘째 기록 − 첫째 기록**. 예를 들어 득점 2→4는 `goals: 2`다.
  보호구 잔여량 차이는 퍼센트포인트이며 접촉은 사람 기체(id=0)만 센다.
- `recorded_conditions_match`: 스키마·소스 지문·빌드 버전·모드·상대 대수·난이도·시드·자동 검사 표시가 일치하는지.
- `eligible_for_deltas` / `reasons`: 차이 계산 허용 여부와 차단 사유.
- `same_training_conditions_verified`: 항상 `false`. 저장되지 않은 조건까지 확인하지 않는다.

기록 조건이 다르거나 같은 세션 ID의 복사/저장 재시도이면 차이를 계산하지 않는다.
자동 검사 세션, 중도 종료, AI 착륙 미완료, 3분 창(179~181초) 밖의 결과도
`deltas: {}`와 사유를 출력한다. 두 기록의 요약은 계속 볼 수 있다.
3분 창은 기존 AI 대전 진단의 허용 범위이며 새로운 훈련 성공 기준이 아니다.

종료 코드는 **0: 차이 계산**, **2: 조건/완료 상태로 차단**, **1: 입력 오류**다.
잘못된 스키마·자료형·범위·시각·기체 목록·중복 JSON 키·손상 파일은 오류로 처리한다.
파일은 네이티브 로더와 같은 65,536바이트 한도를 적용한다. UTF-8 BOM도 지원한다.
스키마1 수비 기록도 읽되 미기록 상대 득점을 0으로 만들지 않는다.
선택 필드 `recovery_attempts`는 양쪽에 있을 때만 차이를 출력한다.

## 해석 제한

레이트/Expo·보정·입력 방식·배터리 시작 상태·전체 시작 장면은 이 결과 형식에 없다.
기록 조건이 같아도 완전히 같은 훈련 조건이나 실력 향상을 증명하지 않는다.
득점·보호구는 종료 요청 시점의 게임 관측값이며 실기체 성적·실물 재질 수명·인증된
온라인 순위가 아니다. `landing_seconds`는 AI 상대의 착륙 시간이다.

## 전달 당시 적용 전 확인 — 이력

아래는 전달 당시의 지침이다. 현재 세 파일은 위 로컬 기준으로 검토·통합했으므로 두 패치를 추가로 적용하지 않는다.

**전달 당시에는 최신 사용자 PC 소스와 대조 전 적용할 수 없다고 안내했다.**
전달 묶음 제작 당시에는 클라우드에서만 구현·검사했으며 사용자 PC·공유 프로젝트·GitHub에는 적용하지 않은 상태였다. 현재 별도 로컬 통합·CLI 검사 상태는 위 현황을 따른다.

- 패치 기준: main `cf3430aa091d3de5d8f470adfa056c6781a22aaa`.
- 저장 형식 대조: 공개 `v0.7.13-rc1`의
  `187e3002dbdecd1c429ca652d106fcc21d69b5b4`에서
  `ImperialAIResults.cpp::ParseResult/SerializeResult`와 `AITraining.h::Settings`를 확인했다.
  기준 main 자체에는 이 AI 결과 저장 코드가 없으며, 새 도구가 이를 main으로 이식하지 않는다.
- 기존 저장 재시도·첫 비행 단계 재시도는 그대로 둔다. 기존 `run-ai-difficulty.py`는
  자동 진단 결과 비교로, 개인 `TrainingResults/AI` 결과 비교와 입력 형식이 다르다.
- 기준 main과 태그에는 `.agents/skills`가 없다. 제공된 `AGENTS.md`와 필수 문서를 따랐다.

전달 묶음에는 패치 두 개가 있다.

- `ai-result-comparison.patch`: 새 파일3개와 기존 체크리스트/검증 문서2개를 포함한 기준 main용 전체 패치.
- `ai-result-comparison-additions.patch`: 새 도구·테스트·이 가이드3개만 포함한다.
  공개 태그와 main의 문서 차이를 피하며, 체크리스트/검증 기록은 최신 문서에 수동 반영한다.

격리된 클라우드 파일 사본에서 `git apply --check`만 수행했다. 전체 패치는 기준 main에서
통과했으나 공개 태그에서는 기존 문서2개의 문맥 차이로 실패했다. 추가 파일 패치는
두 기준 모두 통과했다. 이는 사용자 PC의 현재 상태에서 적용 가능하다는 증거가 아니다.

별도 검토 사본에서 새 도구와 최신 저장 스키마·동명 파일·관련 지침을 대조한다.
일치가 확인되면 **그 검토 사본에서** 먼저 아래 검사만 수행한다.

```powershell
git apply --check "경로\ai-result-comparison.patch"
```

공개 태그에 가까운 최신 사본은 위 명령의 파일명을
`ai-result-comparison-additions.patch`로 바꿔 검사한다. 두 패치는 새 파일이 겹치므로
동시에 적용하지 않는다. 적용 검사를 통과해도 앞서 요구한 최신 로컬 대조가 먼저다.

최신 로컬 대조를 마치고 적용한 검토 사본에서는 다음 독립 검사를 실행한다.

```powershell
python Tests/test-ai-result-comparison.py
python Tests/test-flight-session.py
git diff --check
```

정상·조건 불일치·중단된 실제 저장 기록으로 읽기 전용 출력을 추가 확인한다.
새 UI·게임 연결은 없지만 Unreal 빌드·Windows 게임 실행·실물 조종기·다른 PC 검사는
이 클라우드 작업에서 수행하지 않았다. 이 패치로 재시도/기록 비교 전체를 완료 처리하지 않는다.
