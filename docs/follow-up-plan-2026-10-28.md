# 후속 기획: 탑건 국가별·세계 통합 기록판과 다국어

작성일: **2026-10-28**. **요구 정리와 설계 초안이며 기능 구현·서버 연결·번역 검수 완료가 아니다.** 현재 최우선은 한국어 첫 비행 안내와 작은 글씨·화면 가독성이다. 이 문서는 그 작업을 대체하거나 온라인 개발을 먼저 시작하는 지시가 아니다.

이번 확정 요청은 ① 탑건 기록의 국가별 순위와 전세계 통합 순위, ② 한국어·영어 이후의 다국어 확장 계획이다. 아래 세부 정책은 검토할 제안이며 운영 환경·비용·출시 일정은 미정이다. 문서 작성 과정에서 서버·계정·서비스·접근 권한·결제를 만들거나 바꾸지 않는다.

기존 [통합 계획의 탑건·프로필·기록방](master-development-plan.md#topgun)과 [언어·사용성](master-development-plan.md#experience), [326개 기능 명세](simulator-feature-plan.md)를 확장한다. 기존 로컬→LAN→온라인 기록방을 다시 구현한 것으로 표시하지 않는다. 별도 R11 폴더에서 진행 중인 Topgun 코스 작업도 이 문서 작성으로 병합·검증된 것이 아니다.

상태 표시는 [통합 계획의 범례](master-development-plan.md#status-legend)에 따른다. **구현완료·개발중·미구현·검증대기·확인필요**를 구분하며 기획 문서 작성만으로 실행 기능을 구현완료로 표시하지 않는다.

## 2. 탑건 국가별·전세계 통합 순위

### 2.1 사용자 흐름과 국가 선택

1. 로컬에서는 닉네임과 임의 프로필 ID로 연습하고 개인 기록을 보존한다. 온라인 계정 ID와 로컬 ID는 구분한다. 닉네임 변경이나 동명이인을 별도 선수로 잘못 집계하지 않는다.
2. 국가/지역 표시는 사용자가 자발적으로 선택한다. **미선택을 허용**하고 IP·위치·PC 언어·이름에서 추정하지 않는다. 선택은 자기 표시이며 국적 증명이나 국가 대표 자격을 인증하지 않는다. 국가 목록·코드·표시명·목록 버전은 구현 전에 확정한다.
3. 세계 통합 순위는 같은 비교 조건에 속한 모든 공개·검증 완료 기록을 보여준다. 국가를 선택하지 않은 사용자도 세계 순위에 참여할 수 있다. 국가별 화면은 동일한 기록 집합에 국가 필터를 적용하며 별도 규칙의 경기로 만들지 않는다.
4. 국가 변경 정책 초안은 **새 시도부터 적용하고 기존 기록의 국가 표시는 제출 당시 값으로 고정**하는 것이다. 과거 기록을 조용히 다른 국가 순위로 이동시키지 않는다. 정정·공개 철회와 관련된 예외, 변경 이력의 보관 범위는 공개 전에 확정한다.
5. 온라인 제출 직전에 표시할 닉네임·선택 국가·기록·비교 조건과 공개 범위를 미리 보여준다. 국가 선택과 전체 기록 공개 동의를 같은 선택으로 묶지 않는다. 공개를 원하지 않으면 로컬 기록을 계속 이용할 수 있다.

표시 순위의 단위는 **코스와 조건별 개인 최고 기록**을 기본안으로 한다. 전체 시도 목록·행사/시즌 순위·방 순위는 별도 화면으로 구분한다. 국가별 선수 수 차이와 순위 표본을 확인할 수 있게 하고, 단순 국가별 참가자 수를 실력 순위로 해석하지 않는다.

### 2.2 같은 조건끼리 비교하기

다음 항목을 정규화한 비교 조건 지문을 기록하고, 서버가 허용 조건과 대조한다. 클라이언트가 제출한 지문 문자열만으로 실제 실행 조건을 인증하지 않는다.

| 비교 기준 | 보존할 내용 | 다른 조건의 처리 |
|---|---|---|
| 코스 | 코스 ID·버전·장애물/체크포인트 배치 지문 | 다른 코스·방향·통과 순서를 같은 순위에 넣지 않음 |
| 규칙 | 통과 순서·방향·보호구 여유·충돌/벌점·무효 조건·시도/완주 기준 | 규칙 변경 시 비교 버전 분리 |
| 빌드 | 실제 코드/콘텐츠 입력 SHA-256·지원 실행본 목록 | 초기에는 검증된 같은 빌드끼리 비교. 서로 다른 빌드를 합칠 경우 사전 호환 검증과 명시적 허용 목록 필요 |
| 기체·물리 | 기체/질량·중력·모터/배터리·물리/시간 계약의 버전과 실행 설정 | 물리적으로 다른 성능을 같은 기록으로 취급하지 않음 |
| 보조 | 자동 조종·고도/위치 보조·시간 배율·훈련 보조의 실제 적용 상태 | 허용하지 않은 보조·배속·중도 설정 변경은 제출 자격 없음 |
| 판정 계약 | 서버의 시각 기준·시간 단위/정밀도·시작/완주 사건·비교 스키마 버전 | 다른 계약을 자동으로 합치지 않음 |

기존 통합 계획대로 **Mode1/2·레이트·Expo 같은 입력 취향만으로 순위표를 불필요하게 나누지 않는다.** 필요한 재현 정보는 기록하되, 순위 구분은 공통 규칙이 허용하는 물리 성능과 조종 보조에 따라 정한다. 표시 언어·닉네임·국가는 비교 조건 지문에 넣지 않는다. FPS나 PC 차이의 허용 범위는 실제 시간 계약/물리 검증으로 정하며 서로 다른 환경의 Chaos 궤적이 완전히 같다고 보장하지 않는다.

시간은 화면 문자열이나 PC 시계를 읽어 확정하지 않는다. 원시 판정 정밀도·동률 순위·표시 반올림·동률 정렬 기준은 서버 계약에서 고정한다. 표시 반올림 때문에 서로 다른 기록의 순서를 임의로 바꾸지 않는다. 무효 처리·정정 이후의 개인 최고와 순위 재계산도 같은 규칙으로 검사한다.

### 2.3 오프라인 기록과 온라인 등록 상태

아래 상태와 실패 이유를 한국어로 분명히 보여준다. 인터넷이 끊겼다고 개인 최고 기록이나 진행 중인 로컬 시도를 지우지 않는다.

| 상태 | 의미·다음 행동 |
|---|---|
| 로컬 기록 | 이 PC에서 저장한 기록. 온라인 검증이나 공개 순위 등록을 뜻하지 않음 |
| 제출 자격 확인 | 코스·허용 빌드·물리/보조 조건·공개 동의 확인. 부족한 조건을 먼저 안내 |
| 전송 대기/재시도 | 사용자가 제출을 선택했으나 전송되지 않음. 취소·재시도 가능 |
| 서버 검증 중 | 서버가 세션·시각·통과·조건을 확인 중. 완료 순위처럼 표시하지 않음 |
| 검증 완료/공개 | 같은 조건의 순위에 반영됐으며 서버 영수증과 기록 ID가 있음 |
| 거부/보류 | 버전 불일치·손상·조건 변경·증거 부족 등 이유 표시. 자동으로 부정행위 확정으로 단정하지 않음 |
| 정정/공개 철회 | 원래 결정과 후속 처리 구분. 순위·개인 최고 재계산 및 사용자 통지 |

각 시도에 실행 ID, 제출에는 중복 방지 ID를 사용한다. 같은 ID·같은 내용의 재시도는 같은 서버 기록/영수증으로 돌아오고, 같은 ID에 다른 내용이 오면 충돌을 거부한다. 전송 성공 후 응답만 잃은 경우도 이중 등록하지 않는다. 만료·재접속·대기 취소의 상태 전이를 검사한다.

오프라인 파일·CSV·리플레이·영상 또는 클라이언트가 서명한 지문만으로 공식 온라인 기록을 자동 승인하지 않는다. 오프라인 기록을 검증된 순위로 이관할 수 있는지는 미정이며, 서버가 증거를 확인할 수 없는 기록은 로컬/미검증으로 유지한다.

### 2.4 서버 검증·위조 대응·분쟁

- 공식 순위 후보는 서버가 발급한 실행 세션과 허용 코스/설정에 연결한다. 서버가 승인 입력과 시작·체크포인트·완주·충돌/무효 사건의 순서·시각을 검증한다. 서버 권한으로 판정할 범위와 네트워크 물리 방식은 작은 실험으로 결정한다.
- 변조한 로컬 기록·임의 시간·설정 지문 위조·재전송·만료 세션·불가능한 사건 순서·순간 위치 변경을 거부하거나 조사 대상으로 분류한다. 서명/해시가 있다는 이유만으로 클라이언트 동작 전체를 신뢰하지 않는다.
- 검사 누락이나 모든 치팅 방지를 보장하지 않는다. 이상 기록과 확정 위반을 구분하고 근거·판정 버전·재검토 이력을 남긴다. 부정행위 의심만으로 공개적으로 사용자를 단정하는 화면을 만들지 않는다.
- 이의 제기에는 기록 ID·사유·판정에 필요한 사건 구간을 연결한다. 제출/보류/결정/정정과 순위 복원 절차, 검토 권한, 응답 기준은 운영 전 확정한다. 최초 판정 자료를 수정 자료로 덮어쓰지 않는다.

### 2.5 개인 정보·운영과 비용

공개 표시는 닉네임·자발 선택 국가·기록·코스/조건·검증 상태를 기본 초안으로 한다. 실명·생년월일·개인 보정·전체 PC 경로·장치 고유값·인증 토큰은 공개 순위에 필요하지 않다. 실제 수집 필드·접근 권한·보관 기간·삭제/공개 철회 절차와 필요한 안내는 서비스 도입 전에 확정한다. 원시 입력/상태 기록이 검증에 필요하면 공개 표와 분리해 최소 범위·제한된 권한으로 취급하는 방식을 검토한다.

인증 방식·서버/DB/중계 사업자·지역·호스팅 비용·기록 저장량·대역폭·백업·운영 담당자·장애 대응은 **미정**이다. 비용 약정이나 서비스 계정 생성은 이 기획의 실행에 포함하지 않는다. 추후 소규모 접속/부하 시험 결과로 필요한 범위와 예산을 제시한다. 서버 장애·검증 지연은 사용자에게 상태로 표시하고 기존 로컬 기록을 유지한다. 운영 재개 시 중복 제출·누락·순위 불일치를 점검한다.

기존 기능 연결: `TRN-03/08/09/14`, `TEAM-02/10/11`, `NET-01/03/09/14`, `LOB-09`, `OPS-01~08`. 이번 문서는 나라별·세계 통합 상시 순위를 온라인 기록방의 추가 요구로 정리하며 기존 기능을 완료로 체크하지 않는다.

## 3. 다국어 확장

### 3.1 현재 지원 범위

공개 `v0.7.12-rc1`의 실제 경로는 `ImperialLocalization.cpp`의 영어 원문/형식 문자열→한국어 표와 `ko/en` 선택이다. 한국어가 기본이며 `Config/Language.txt`에 사용자별로 저장한다. `-ImperialLanguage=ko/en` 실행 인자는 세션 선택이고 저장 파일을 다시 쓰지 않는다. 번역을 찾지 못하면 현재 코드는 원문을 남긴다. 이 구조는 조종기 중심 지원이며 전체 AI/경기/결과 화면 번역이나 다른 언어 지원을 뜻하지 않는다.

별도 로컬 AIUI1은 AI 설정/결과81개 번역과 한/영 전환을 추가했다. 새 통합 작업본은 이 변경과 관측형 첫 비행을 통합해 최종 지문으로 다시 검증한다. 별도 빌드의326개 검사와 예비 빌드 결과를 새 실행본의 성과로 합산하지 않는다. 한국어/영어의 부분 지원과 모든 화면 번역, 추가 국가 언어 지원은 각각 구분한다.

먼저 한국어 첫 비행·조종기 안전 용어를 완성한다. ARM/DISARM·스로틀·러더/기울기·Mode1/2·방향·연결 손실·거부 이유와 다음 행동의 뜻이 일관돼야 한다. 표시 언어 변경은 저장 보정·입력 장치·축·스로틀·비행 모드·모터 상태를 바꾸지 않는다.

### 3.2 문자열·리소스 구조의 후속안

1. 영어 문장 자체를 조회 키로 사용하는 경로를 점진적으로 안정된 의미 키로 옮긴다. 예: `controller.radio.enable`, `safety.arm.throttle_high`, `first_flight.takeoff.instruction`. 문구 수정이 키·상태 ID나 다른 언어를 우연히 깨뜨리지 않게 한다.
2. 언어별 리소스·기본 문자열·용어표·검수 상태를 분리한다. 리소스는 텍스트 데이터로 취급하고 실행 코드로 해석하지 않는다. 리소스 버전·필수 키·중복 키·형식 인수와 단위를 검사한다. Unreal의 현지화 리소스 사용 여부와 기존 Canvas/FString 경로 이관 방식은 구현 전에 비교한다.
3. 시간·복수형·숫자/단위·어순을 문장 전체의 이름 있는 인수로 처리하는 방향을 검토한다. 번역에서 인수의 이름/형식·부호·단위를 빠뜨리거나 바꾸면 검사 실패로 처리한다. X/Y/Z/R/U/V와 실제 장치명·기록 ID·버전·해시는 식별값으로 유지한다.
4. 누락 대체 표시의 초안은 **선택 언어 → 검수된 기본 영어 → 식별 가능한 안전한 오류 안내**다. 한국어 필수 안전/첫 비행 키는 출시 전 누락0을 요구한다. 개발 검사에서는 누락 키·대체 표시 여부를 식별하고, 일반 화면에 내부 키나 긴 경로를 노출하지 않는다.
5. 국가 선택과 표시 언어를 서로 추정하지 않는다. 언어 변경/재실행·설정 저장 실패·지원하지 않는 언어 값·이전 설정의 복구를 검사한다. 개인 언어 설정과 보정 파일은 배포 ZIP에 넣지 않는다.

한국어와 영어 리소스를 우선 분리하고 기존 동작을 대조한 뒤 다음 언어를 정한다. 기계 번역·리소스 파일 존재·자동 검사 통과만으로 새 언어를 지원 완료로 표시하지 않는다.
