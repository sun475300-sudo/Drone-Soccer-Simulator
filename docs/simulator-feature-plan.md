## 범위와 우선순위

정식 목표는 Windows Unreal 기반 **수동 드론축구 경기·개인/팀 훈련·Boxer 연결·온/오프라인 멀티플레이·심판 운영·개발 피드백**이다. 아래 항목을 제품 범위의 전체 관리 목록으로 사용하고, 새로운 요구는 고유 번호로 추가한다. 가능한 모든 확장 기능의 구현을 약속하는 목록은 아니다.

| 우선순위 | 의미 |
|---|---|
| P0 | 실행·조종·입력 손실·물리/통신 안정화. 후속 기능의 전제 |
| P1 | 기본 경기·장비·사용 흐름·진단·배포의 필수 완성 |
| P2 | 여러 사람의 경기·심판/대회·심화 훈련·리플레이 완성 |
| P3 | 기본 제품 검증 후 선택하는 연구·외부 연동 확장 |

| 현재 상태 | 의미 |
|---|---|
| 기본 | 현재 소스·검증 문서에 기본 구현이 있음. 해당 행의 모든 완료 조건 통과를 뜻하지 않음 |
| 보강 | 일부 구현·이전 시험이 있으나 기능 보강·현재 패키지 재검증·실측 등이 필요 |
| 신규 | 현재 배포본의 지원 기능으로 확인하지 못한 개발 항목 |
| 선택 | 도입 여부·비용·검증 조건부터 결정할 확장 |
| 완료(문서) | 해당 문서 작성·근거 대조·링크 검수를 완료함. 실제 다른 PC·조종기 현장 시험 완료를 뜻하지 않음 |

**완료 처리 공통 조건:** 기능 동작, 사용자 안내, 적용 범위, 실패/복구 동작, 버전이 붙은 검증 근거를 함께 남긴다. 구체 허용 오차·성능 목표가 정해지지 않았다면 먼저 기준을 합의·측정하고 완료로 표시하지 않는다. 표의 완료 조건은 목표이며 이번 작업의 시험 결과가 아니다.

## 유지해야 할 현재 기준

- LOS를 기본 시점으로 두고 모든 수동 기체는 ANGLE을 사용한다. Yaw·스로틀은 직접 조종한다.
- Striker는 양 팀 **자기 시작선 중앙**. 사용자 지정 하단 띠는 Striker 초록·Guide 분홍, 좌우 각각 2개다.
- 기본 규정은 FIDA Class40이며 다른 단체·대회 규정은 별도 프로필로 검증한다.
- 공식 수동 경기와 SDACS 자동 Practice를 분리한다.
- 정상 비행은 모터 힘·토크와 물리로 처리하고 리셋 외의 편의상 순간이동을 사용하지 않는다.
- 물리 가정과 실측, 시각 흔들림과 실제 파손, 10대 배치와 10명 동시 접속을 구분한다.
- 실물 Boxer의 실제 보정은 있으나 연속 비행·케이블 손실/복구·지연 검증은 미완료다.
- v0.6의 F6 비행 JSONL 기록·F8 재연결·장치 진단·사용자별 저장을 현재 기반으로 보존한다. 상세 안내는 [포터블 실행 문서](PORTABLE_QUICK_START.ko.md)를 따른다.
- 아래 종속 분야는 작업 순서를 뜻한다. 같은 물리·제어의 상호 의존 관계는 작은 통합 시험으로 함께 해소한다.

| M1. 수동 경기 완성 | RUL·TEAM·REF 필수, PWR·AIR·ARN·DMG의 상태/태그 부분 | 기권/승계·태그 정책·페널티 후 세트 확정. 논리 고장으로 먼저 검수하고 고급 cloth·실제 프레임 파괴를 선행 조건으로 두지 않음 |
| M2. 사용·진단·표현 완성 | DAT·UX·GFX·AUD·PERF·REL·DOC의 P1 | 로컬 진단 미리 보기·삭제, 대표 장면 성능, 별도 PC 설치·실행 |
| M3. 오프라인 동시 경기 | LOC·NET·LOB의 LAN 범위 | 개별 장치·소유권 검증 후 2인→확정 인원, 인터넷 없는 LAN 실제 5대5 |
| M4. 온라인·복기·대회 | NET·LOB·OPS의 비공개 원격 경기부터, RPL·REF·TRN·AI 점진 확장 | 실제 다른 회선5대5·장애/공정성 검수 후 복기·대회 운영 확장. 공개 방 탐색·선택 연구는 별도 결정 |
| M5. 선택 확장 | EXT·LOB-04 등 P3 | M0~M4 완료 범위를 유지하고 별도 실험·비용·권리 검토 |

기본 진단 묶음 DAT-02와 필수 안내 UX/DOC는 M0~M1부터 병행한다. 그래픽 변경도 병행할 수 있지만 조종 지연과 식별성 악화를 먼저 검사한다. AI 연습 상대가 준비되지 않았어도 수동 경기와 사람 간 멀티플레이를 독립적으로 개발한다.

### 첫 착수 작업

1. **AI-11, INP-05, INP-06, INP-12:** 수동 경기의 HOLD/RETURN·내부 자율 진입 경로를 우선 제한한다. 저장한 실제 Boxer 보정을 보존하며 연속 비행·분리/재연결·입력 지연 시험을 준비한다.
2. **CTL-03~05, CTL-13~14, QA-02:** 고정주기 제어의 작은 실험 구현과 기존 물리 시나리오 전후 비교 기준을 정한다.
3. **AI-02~04:** 현재 세션/명령/요청 처리를 유지한 채 실제 UE 임무·귀환 중 통신 장애를 시험한다.
4. **RUL-05~09, RUL-15~17, DMG-09~13:** 팀별 현재 공격수·태그 자격·기권/접촉/승계 상태도를 먼저 정리한다.
5. **DAT-02, DAT-05, DOC-07:** 현재 로그·CSV로 시작하는 로컬 진단 묶음과 피드백 양식을 만든다.
6. **NET-01~03, NET-13~15, LOC-02:** 작은 네트워크 물리 시험과 실제 2개 USB 입력의 독립성을 확인한 뒤 확장한다.

번호 범위는 해당 기능들을 뜻하며, 목록 등록 자체로 구현에 착수했다고 보고하지 않는다.

## 전체 기능에 공통으로 적용할 검수

| 검수 영역 | 반드시 남길 근거 |
|---|---|
| 기능·권한 | 정상 조작, 거부 조건, 잘못된 기체/역할 명령, 취소·복귀 결과 |
| 입력·물리 | 실제 USB/수치 fixture 구분, 단위·좌표·주기·모델 설정, 힘 기반 실제 궤적 |
| 경기 | 적용 규정 판본, 상태 전이, 경계 사건, 최종 판정 사유 |
| 멀티플레이 | 서버/클라이언트 버전, 인원·회선, 지연·손실, 입력 소유권·상태 일치 |

| 데이터 | 수집 범위·샘플 간격·보관, 사용자 미리 보기·삭제·공유와 실제 파일 내용 |
| 배포 | 소스 입력 지문, 실행 파일 버전·해시, 의존성·권리 고지, 별도 PC 재현 |
