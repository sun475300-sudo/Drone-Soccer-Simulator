# 탑건 로컬 코어 — 2026-10-31

## 목적과 계획 연결

- 이 문서는 별도 Topgun 작업의 **엔진 독립 로컬 코어** 범위를 기록한다.
- 통합 개발 계획서의 20개 작업 묶음 중 **10번 탑건 기록전**에 연결한다.
- 10번 묶음의 계획상 상태는 별도 개발본·실행본 대조가 필요한 `확인필요`이며, 이 파일 작성만으로 통합 완료가 되지 않는다.
- 20개 묶음 표의 번호 10은 기능 ID가 아니라 사용자 요청 묶음 번호다.
- 이 작업은 피드백 **12번**의 “탑건 2기둥 S코스·방 기록·닉네임/ID/국적”을 좁은 코어로 구현한다.
- 개발 단계는 **C 탑건 로컬**이다.
- C 단계의 출구 기준은 2기둥 코스·판정·타이머·프로필·로컬 기록과 방향·순서·무효·저장/재실행 검사다.
- 관련 기능 ID는 `TRN-03`(게이트 순서·통과 시간), `TRN-08`(실패 뒤 재시작) 및 `TRN-14`(버전 있는 훈련 과제 데이터)다.
- 프로필·기체 소유권·독립 식별의 후속 연결은 `TEAM-01`, `TEAM-02`, `TEAM-04`, `TEAM-08`, `TEAM-10`, `TEAM-11`이다.
- 상태·사건을 후속으로 복기할 때는 `RPL-01`~`RPL-11`, 특히 버전 호환 `RPL-08`과 판정 증거 `RPL-11`을 연결한다.
- LAN/온라인 기록방은 이번 범위가 아니며 `NET`, `LOB` 및 단계 H/I의 별도 과제다.

## 생성 파일과 책임

- `Source/ImperialWingsSimulator/TopgunCourseDraft.h`(namespace `ImperialTopgunLocal`, 게임 미연결 초안)는 Unreal 헤더 없이 쓰는 C++17 코스 판정기다.
- `Source/ImperialWingsSimulator/TopgunRecords.h`는 로컬 프로필·시도·최고 기록·직렬화 코어다.
- 두 헤더는 파일 I/O, 난수 생성, 네트워크, Unreal 타입과 전역 가변 상태를 사용하지 않는다.
- `Tests/topgun_tests.cpp`는 `main()` 기반의 독립 검사이며, `Tests/run-topgun-tests.ps1`는 Windows MSVC 검사 경로를 준비하지만 이 Linux 환경에서는 실행하지 않았다.

## 코스 정의와 상태 기계

- 코스 버전은 `topgun-s2-draft-1`이다.
- 단계는 `Idle → AwaitStart → PassPillarOneSide → PassBetweenPillars → PassPillarTwoOppositeSide → PassFinish → Finished`다.
- 무효 상태는 어느 활성 단계에서도 `Invalid`로 단방향 전이한다.
- 전진 축은 +X이며, 출발선 뒤에서 첫 기둥의 +Y 쪽, 두 기둥 사이, 두 번째 기둥의 -Y 쪽, 결승선 순서로 지난다.
- 각 통과는 이전 보호구 중심과 현재 보호구 중심 사이의 **선분**을 검사한다.
- 따라서 한 프레임에 첫 기둥 측면과 기둥 사이 선을 모두 지나도 순서대로 판정하며 빠른 통과를 프레임 끝점만으로 놓치지 않는다.
- 교차 위치는 X 평면과 선분의 교점을 사용하고, 교차 시각은 같은 선형 비율로 호출자 제공 시뮬레이션 시계에서 보간한다.
- 시작 시각은 출발선 교차 시각이며, 완주 시간은 결승선 교차 시각에서 시작 시각을 뺀 값이다.
- 기체 보호구 전체가 안전 구역에 들어가야 한다.
- 각 구역의 Y/Z 경계는 가드 반경만큼 안쪽으로 줄이고, 수직 기둥에는 기둥 반지름과 가드 반경의 합보다 큰 수평 여유를 요구한다.
- 결승은 두 번째 기둥 측면 통과와 별도 단계이므로 기둥 통과만으로 완주하지 않는다.
- 역방향 이동은 `ReverseDirection`, 필수 중간 구역 누락은 `SkippedZone`, 첫/두 번째 기둥의 잘못된 측면은 `WrongSide`로 기록한다.

## 시간·조건·충돌 정책

- 호출자는 단조 증가하는 `SimulationClockS`와 실제 물리 진행량 `PhysicsDeltaS`를 제공한다.
- `dt <= 0`, 비유한 수, 최대 프레임 간격 초과, 시계와 물리 시간의 과도한 차이는 `PhysicsTimeGap` 또는 `NonMonotonicClock`으로 무효다.
- 명시적 RESET, 기체 ID 변경, 물리·중력·보조 설정 개정값 변경, pause, 비정상 시간 배율도 무효다.
- 충돌 수는 누적하되 연습 시도는 즉시 중단하지 않는다.
- 초안 기본 정책은 충돌 0회만 `OfficialRecordEligible=true`로 두며, 충돌 뒤에도 연습 완주·피드백은 가능하다.
- 정책을 명시적으로 바꾼 초안은 충돌 후 적격 표시를 허용할 수 있지만, 어떠한 행도 온라인 검증 기록이 되지 않는다.
- 모든 결과는 로컬/미검증이며 서버 판정·방 동기화·변조 방지는 구현하지 않았다.

## 프로필과 기록

- 닉네임은 사용자가 입력하며 중복을 허용한다.
- 닉네임은 1~24 UTF-8 코드 포인트, 제어 문자 제외, 공백만 금지로 검사한다.
- 프로필 ID는 RFC 4122 v4 텍스트 UUID로 검사한다.
- `FormatUuidV4`는 호출자가 준 128비트 난수만 형식화하며 내부 난수 생성은 하지 않는다.
- 국적은 비어 있거나 대문자 ISO 3166-1 alpha-2 할당 코드여야 하며 자동 추정하지 않는다.
- 닉네임 변경은 동일 프로필 ID를 유지하므로 이전 시도는 새 선수로 분리되지 않는다.
- 시도 ID 중복은 거부한다.
- 시도는 코스/규칙 버전, aircraft/physics/gravity/assist/build 조건 키, 완주 시간, 유효성, 무효 사유, 충돌 수를 가진다.
- 유효 기록의 무효 사유는 `None`이어야 하고, 무효 기록은 명시적인 무효 사유와 함께 남긴다.
- 개인 최고와 이 PC의 로컬 최고는 같은 코스·규칙·전체 조건 키 안에서만 조회한다.
- 동점이면 먼저 저장된 시도가 우선이므로 순서가 결정적이다.
- 비교 대상 시도에는 개인·로컬 최고와의 초 단위 차이를 제공한다.

## 저장 형식과 손상 방어

- 직렬화 형식은 `TOPGUN_RECORDS|1` 헤더를 쓰는 버전 있는 줄 단위 텍스트다.
- 프로필과 시도 문자열은 `\`, `|`, 줄바꿈, CR을 이스케이프한다.
- 실수 시간은 IEEE 754 64비트 비트열의 16진 표현으로 저장해 표시 지역화에 따라 값이 달라지지 않게 한다.
- 페이로드 뒤에는 FNV-1a 64-bit 체크섬 행을 쓴다.
- 파서는 빈 입력, 잘린 입력, 잘못된 헤더, 미래 버전, 체크섬 불일치, 잘못된 이스케이프, 잘못된 행을 명시적 `ParseError`로 구분한다.
- 파싱은 임시 저장소에서 모두 검사한 뒤에만 호출자 저장소를 교체하므로 실패 시 이전 데이터가 보존된다.
- 헤더는 미래 버전을 체크섬보다 먼저 식별해 호출자가 업그레이드를 안내할 수 있게 한다.
- 이 헤더는 디스크 잠금·원자 파일 교체를 하지 않는다. 실제 저장은 기존 `ImperialProfileStorage.cpp`의 보존 정책과 통합해야 한다.
