## 현재 착수: R9 CTL-13 읽기 전용 solver probe

개발 버전은 **v0.7.5-dev**, 브랜치는 `codex/r9-solver-probe`다. 기존 R8 배포와 분리해 callback 카운터만 관찰한다. 공식 다운로드 v0.7.4-r2를 교체하지 않으며 이번 작업에 새 일반 사용자 릴리스는 계획하지 않는다.

1. 명시적 진단에서 solver callback 횟수·순서·시간을 기록하는 소스를 추가했다. 기체/컴포넌트/강체 proxy 접근이나 PID·힘 적용은 추가하지 않는다.
2. 동일 입력 지문 `1a6b144d1404dfc32b5336125d5236f9ad3f97f0ab3019b9378943cd90cf955f`에서 최종 Editor·새 경로 Shipping의20/30/45/60/120/240FPS·동기/fixed120 각8초, 합계24개 카운터 조건과8개 옵션 거부를 통과했다. fixed120은 DISARM 카운터 실험이며 비행 제어기의 고정주기 이관이 아니다.
3. 두 실행본의43초 시나리오 baseline/observer 비교2쌍과 포터블13개를 통과했다. observer는 예열 후 월드0.516667~43.016669초·완료 tick을 포함하며 장부 오차 약1.75e-12초다. [최종 실험 보고서](solver-probe-2026-10-27.md)와 [결과](verification/solver-probe-2026-10-27.json)에 범위·실패 이력을 연결한다.
4. 카운터 검사 통과는 계측 하위 단계만 완료한다. 통과한 호버·네트·골대와10대 종료 위치/속력/SOC/전압 비교는 연속 궤적·속도 벡터·전체 에너지 적분 동등성의 근거가 아니다. 아래 후속 단계에서 게임 물리 프레임별 비교를 추가하며, solver 상태 전달·단일 힘 경로 이관·고정120Hz 비행 제어는 별도 후속이다. 그래픽 개선·실물/새 하드웨어 검증도 완료 처리하지 않는다.

## 현재 후속: 프레임별 비교 완료·상태 전달/힘 이관 전

같은 브랜치의 v0.7.5-dev, 최종 입력127개·지문 `71aa36b021080fcbc262ed1820ba6d169e7d3fc36651e3978beb690a2eb8515e`에서 검사했다. 앞선 카운터 결과를 보존하며, 종료 상태만 비교했던 한계를 현재 게임 물리 프레임 해상도에서 보완했다. 공식 v0.7.4-r2 다운로드는 변경하지 않으며 새 r2 ZIP은 로컬 QA용이다.

1. 첫 기준 샘플 이후 완료 프레임까지 매 동기 게임 물리 프레임의10대 위치·회전·선속도/각속도·전류·SOC·전압·소모Ah·모터 전력을 기록한다. 매 프레임 물리 갱신 순번+1과0번 기체3회 reset, 나머지9대 무reset을 검사한다.
2. 독립 분석기로 프레임별 전류 직사각형 적분과 소모Ah/SOC, `V*I`·공급 에너지·모터 에너지 및 baseline/observer 차이를 확인한다. 같은FPS끼리 비교하며 서로 다른FPS의 동일 궤적을 요구하거나 주장하지 않는다.
3. Editor·Shipping20/30/45/60/120/240FPS각6쌍과 새 경로 ZIP60FPS1쌍, 총13쌍·26회가 통과했다. 실행당 기체 샘플 수는 FPS 순서대로8600/12900/19350/25800/51600/103200, 합계937,400행이다. 같은FPS 쌍의17자리 CSV 해시가 모두 일치하고 전류/에너지 적분 차이는0이다. 동일 quaternion의 각도 재계산 잔차는 최대2.98e-8rad다. Editor·Shipping·새 ZIP의 최종 분석기 각18개·새 포터블13개·최신 Shipping 카운터12개/옵션 거부4개도 통과했다.
4. 추가 거부 검사에서 UE5.8의 파일 생성 플래그만으로 기존 CSV를 보호하지 못하는 문제를 찾았다. 명시적 존재 확인으로 고친 뒤 원본 CSV 보존을 포함한 옵션6개·전체 비교·새 ZIP 검사를 최종 지문에서 다시 통과했다.
5. 이 결과는 Chaos 내부 서브스텝 궤적이나 실제 고정120Hz PID·힘 이관 완료가 아니다. 다음 개발 관문은 단계2 상태 버퍼의 안전한 전달과 단일 힘 경로 이관이며, GPU·실물 USB·새 하드웨어·다른 물리 PC 검증은 별도다.

## 현재 완료: 별도 강체의 입력·힘 연결 기반 검증 / 다음: 한 대의 비행 모델 이관

같은 `codex/r9-solver-probe` / v0.7.5-dev의 최종129입력·지문 `4ed812ec3ebad3bee96ec4c4235dbf060ac1e53ff54a4038d1dd5a070b7bb838`에서 검사했다. 질량2kg·반지름0.25m의 별도 구형 강체를 사용하며 일반 드론의 PID·힘 경로·기본 물리 설정과 공식 다운로드 v0.7.4-r2는 유지한다.

1. 게임 스레드의 입력 스냅숏과 물리 callback의 완료 출력 전달을 구현했다. 입력 순번·바인딩 세대·발행 시각·유효 기간과 실제 내부 강체 상태를 기록한다.
2. 실제 solver 단계마다 힘과 질량중심 기준 토크를 한 번씩 적용하고 단계별/누적 속도·각속도 변화를 독립 해석값과 비교했다. Editor·Shipping 여섯FPS각6회와 새 경로 ZIP20/45/240FPS3회, 총15회·12,087단계를 통과했다.
3. 9개 입력 구간에서 DISARM·오래된 입력·세대 불일치·비유한 입력·같거나 지난 순번의 새 표본을 차단하고 새 ARM의 힘 재개를 확인했다. 입력 만료는 solver 시각 기준이며 실제 USB 지연·벽시계 정지 감시의 검증이 아니다.
4. 각 실행 환경의 분석기19개·옵션 거부4개, 새 ZIP13개를 통과했다. 강체를 유지한 callback 등록 해제·소멸 확인과 이후 호출0회·속도 변화0을 확인했다. 같은 최종 소스 Shipping60FPS의43초 정상10대 비행 baseline/observer1쌍·분석기18개도 통과했다. 이 결과를 기체 파괴/재생성·비동기 수명 전체 검증으로 확대하지 않는다.
5. 다음 단계는 실제 드론 한 대의 센서·PID·모터/배터리 이관이다. 기존 힘 경로와 중복 적용되지 않음을 확인한 뒤 호버·ANGLE 복원·전력·정지,10대·접촉과 정확한120Hz 비행으로 확장한다. CTL-13 전체는 계속 미완료다.
