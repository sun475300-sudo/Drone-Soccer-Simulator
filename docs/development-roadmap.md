# 개발 순서와 완료 기준

**2026-10-27 최신 전체 계획은 [통합 개발 계획서](master-development-plan.md)를 따른다.** 조종기 개선의 현재 검사 결과와 AI→탑건→LOS/UI→경기/물리→LAN/온라인 순서를 그 문서에 통합했다. 아래는2026-10-26부터 작성한 상세 요구·과거 점검 이력으로 보존한다. 당시의 버전·미구현 표시를 최신 상태로 그대로 해석하지 않으며, 기능별 상태는 [전체 명세](simulator-feature-plan.md)와 [검증 기록](verification.md)을 대조한다.

후속 [v0.6.1 변경·검증](releases/v0.6.1.md)에 조종기 간소 화면·장치 카드·저장 연결,실행 GIF와 데이터 수집 안내를 기록했습니다. [타 시뮬레이터 조사](simulator-benchmark.md)는 입력/훈련/복기 계획에, [제공 영상의 물리 대조](video-physics-reference.md)는 실측·비교 계획에 연결합니다. 기존 전체 경기·멀티플레이·고장 기능의 구현 완료를 뜻하지 않습니다.

2026-10-26 사용자 제공 계획을 등록하고 온라인·오프라인 멀티플레이와 개발 피드백 데이터 수집 계획을 추가했습니다. 현재 v0.6.0 포터블 사전 배포와 기존 v0.5.0 안정 배포를 구분하며, 최신 실행 안내는 [포터블 문서](PORTABLE_QUICK_START.ko.md), 실제 완료 범위는 [검증 기록](verification.md)을 따릅니다.

아래의 초기 점검과 1~9·11단계 체크리스트는 R4/R5 당시 작성한 개발 기준을 포함합니다. 96개 화면 검사 등 과거 수치를 현재 버전의 재검사 결과로 사용하지 않습니다. 이미 수행한 작업의 실제 상태는 작업 목록·검증 이력으로 확인하며, 새 10·12단계는 이번에 등록한 미구현 계획입니다.

현재 프로젝트는 **기본 비행·5대5 경기·포지션과 LED·자율 훈련이 구현된 시제품 단계**입니다. 다음 개발은 **Boxer 실조종 완성 → 제어·통신 안정화 → 경기 운영 완성 → 그래픽·성능 개선 → 배포** 순서로 진행하는 것이 좋습니다.

**전체 기능 명세:** [28개 분야·326개 기능 목록](simulator-feature-plan.md)에 기능 번호·우선순위·현재 상태·완료 조건을 정리했습니다. 기존292개를 자체 검토해34개를 추가하고16개를 정밀화했습니다. [정밀 검토·실행 계획](simulator-plan-review.md)의 근거·수치 초안·20개 인수 시나리오를 함께 적용합니다.

소스, 설정, 실행 스크립트, 물리 모델, 경기 판정, 검증 기록을 점검했습니다. 저장된 결과에서 **화면 조작 96개 항목 통과**, **30·60·120Hz 물리 시나리오 성공**을 확인했습니다. 이 문장은 계획 작성 당시의 점검 범위입니다. 이후 변경·실행 결과는 verification.md의 버전별 기록을 따릅니다.

**점검에서 확인한 주요 보완점**

| 분야 | 현재 상태 | 다음에 해결할 점 |
|---|---|---|
| Boxer | 실제4축 보정·프로필 저장·USB 활성화·최저 스로틀 ARM 확인 | 연속 USB 비행·기체 반응 방향·분리/재연결·지연 측정 |
| 비행 제어 | 모터 힘·PID·센서·배터리 모델 있음 | 제어 계산이 화면 프레임에 영향받음 |
| 경기 판정 | 기본 득점·오프사이드·세트 진행 구현 | 공격수 승계·심판 운영·페널티·동점 처리 보강 |
| 자율 훈련 | 실제 APF·세션/명령/요청 번호와 이전 응답 차단 구현 | 현재 패키지의 임무·귀환 중 실제 통신 장애·복구 검증 |
| 기체·LED | 역할색·팀 띠·전후방 표시 구현 | 실제 LOS 거리에서 식별성 검증 |
| 그래픽 | Lumen·재질·경기장·절차적 기체 구현 | 가까이서 보는 자산 품질과 목표 PC 성능 검증 |

| 자동 검증 | 독립·실행·화면 시험 있음 | GitHub 자동 검사와 버전별 결과 연결 필요 |

특히 경기 코드에서 득점 가능한 공격수가 현재 **기체 ID 0·5로 고정**되어 있습니다. 공격수 승계를 추가할 때는 역할·LED·득점 권한이 함께 바뀌도록 구조를 고쳐야 합니다. 자율 통신에는 세션·명령 세대·요청 번호가 구현되어 있으며, 실제 UE 모드 전환·귀환 도중 장애에서 이전 응답 차단을 추가 검증해야 합니다.

아래 목록은 **권장 개발 순서**입니다. 완료 기준을 만족한 뒤 다음 단계로 넘어가도록 잡았습니다.

- [ ] 현재 정상 동작하는 소스·콘텐츠·실행 파일을 같은 버전으로 묶기.
- [ ] 실행 화면에 버전명·소스 커밋·빌드 날짜 표시.
- [ ] 시험 결과에 사용한 소스 커밋과 설정값 기록.
- [ ] 에디터 실행과 배포 실행 파일의 차이 정리.
- [ ] 소스가 바뀌면 기존 실행 파일을 구분해 표시.
- [ ] 엔진·Python·SDACS 경로를 한곳에서 설정하도록 통합.
- [ ] 설치된 필수 도구를 검사하고 누락 항목을 한국어로 안내.
- [ ] 새 폴더에 GitHub 프로젝트를 받아 설치·빌드·실행 재현.

**완료 기준:** 개발 폴더의 기존 임시 파일 없이도 새 복사본에서 실행할 수 있고, 어떤 소스로 만든 실행 파일인지 확인할 수 있을 것.

- [ ] 여러 PC의 내보낸 묶음을 별도 개발 환경에서 열어 오류 발생 구간 재구성.
- [ ] 외부 업로드 없이 생성·미리 보기·삭제가 가능하고 비밀값·개인 프로필 제외 확인.

**완료 기준:** 사용자가 문제 발생 시점을 표시하고 내용을 확인한 진단 파일을 내보낼 수 있으며, 개발자가 버전·설정·입력/사건·성능의 맥락을 읽을 수 있을 것. 동의·보관·삭제가 설명과 일치하고 실제 수집 부하를 측정해야 합니다. 기록만으로 Chaos 비행이 프레임 단위로 동일 재생된다고 보장하지 않습니다.

<a id="complete-feature-plan"></a>
**13. 전체 기능 명세·통합 실행 계획 — 2026-10-26 추가**

[전체 기능 계획서](simulator-feature-plan.md)는 현재28개 분야·326개 기능입니다. 각 행은 고유 번호·P0~P3 우선순위·기본/보강/신규/선택 상태·완료 조건을 갖습니다. 상태는 완료율이 아니며 실제 구현·시험 후에만 갱신합니다.

| 기능 묶음 | 포함 분야 |
|---|---|
| 실행·조종·물리 | 실행/설정, 키보드/USB, 비행 제어, 공력/센서, 접촉/네트, 배터리, 고장/파손 |
| 드론축구 경기 | 기체/LED/띠, 경기장/시작 위치, 규정/득점/승계, 심판/대회, 팀/역할 |
| 훈련·여러 사람 경기 | 입문/포지션 훈련, SDACS/연습 상대, 같은 PC/LAN, 네트워크 물리, 온라인 방 |
| 사용자 경험·개발 | 리플레이, 피드백 데이터, 한국어/접근성, 그래픽, 음향, 성능 |
| 배포·운영·확장 | 검사, 빌드/배포, 문서, 서버/정보 보호, 선택 연구 기능 |

- [ ] 기능 번호를 실제 개발 이슈·검사·릴리스에 연결.
- [ ] M0 조종 안정화 → M1 수동 경기 → M2 사용/진단/표현 → M3 오프라인 동시 경기 → M4 온라인/복기/대회 순서로 검증.
- [ ] 각 기능의 수치 기준·환경·실패/복구·검증 근거를 확정.
- [ ] 기본 제품 검증 후 선택 확장 M5의 비용·권리·필요성을 결정.

**완료 기준:** 목록의 등록을 기능 구현으로 보고하지 않고, 검증된 실행 파일과 실제 시험 결과로 각 완료 조건을 입증할 것. 상세 명세와 기존 계획의 중복 항목은 같은 기능 번호로 관리합니다.
