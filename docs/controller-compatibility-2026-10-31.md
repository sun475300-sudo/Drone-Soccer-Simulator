# USB 조종기 호환 시험표와 지원 목록 기준

작성일: 2026-10-31. 연결 계획 항목은 [통합 개발 계획서](master-development-plan.md#remaining-priorities)의 **5번 USB 호환 확대**, 피드백 3번(모든 USB 조이스틱을 목표로 지원 확대), 4절 조종기 설정 완성의 `범용 입력`·`장치 식별` 행, 기능 명세 INP-02~06이다.

**이 문서는 시험 양식과 판정 기준이다. 새 입력 경로를 구현하거나 새 기종을 시험한 결과가 아니다.** 아래 지원 목록에는 실제 장치로 확인한 조합만 등록한다. Windows가 장치 이름을 표시하거나 장치 열거에 성공했다는 사실만으로는 지원 기종으로 등록하지 않는다.

## 1. 현재 입력 경로

| 항목 | 현재 구현 | 근거 |
|---|---|---|
| 입력 API | WinMM `joyGetDevCapsW` / `joyGetPosEx` | `Source/ImperialWingsSimulator/ImperialRadioSubsystem.cpp` |
| 장치 슬롯 | 드라이버 슬롯 최대 16개를 조회한다. `joyGetNumDevs`는 연결된 장치 수가 아니라 슬롯 수다 | 같은 파일의 장치 열거 주석 |
| 축 | X/Y/Z/R/U/V 6축을 읽는다(`Caps.wNumAxes` 기준 사용 가능 여부 표시) | 같은 파일 |
| 버튼 | `dwButtons` 32비트 버튼 마스크 | 같은 파일 |
| 보정 | 범위 수집 → 중립·최저 스로틀 → 검토 저장 → 별도 활성화 → 별도 ARM | [BOXER_SETUP](BOXER_SETUP.md), `RadioCalibration.h` |

WinMM 경로는 32개를 넘는 버튼, 7번째 이후 축, 장치 고유 일련번호를 제공하지 않는다. 같은 제품 두 대를 동시에 연결했을 때 두 장치를 확실히 구별하는 근거도 없다. 계획서 4절의 원칙에 따라 **식별이 불확실하면 저장된 보정·아밍키를 자동 적용하지 않고 사용자에게 다시 선택하게 한다.**

## 2. 시험 기록 양식

계획서 4절이 요구하는 열을 그대로 사용한다. 한 행은 **하나의 장치·펌웨어·USB 모드·입력 경로·OS·게임 빌드 조합**이다.

| 열 | 기록 방법 |
|---|---|
| 제조사/모델 | 장치 본체에 표시된 이름. Windows 표시명(`szPname`)은 별도 열에 기록 |
| 펌웨어 | 조종기 펌웨어 판번호(예: EdgeTX 판번호). 확인하지 못하면 `미확인` |
| USB 모드 | Joystick/HID, 시리얼, 저장장치 등 조종기에서 선택한 모드 |
| 입력 경로 | 현재는 `WinMM`. 다른 경로를 추가하면 경로마다 별도 행 |
| 축/버튼 수 | `wNumAxes` / `wNumButtons` 실측값과 실제로 움직인 채널 |
| Mode | Mode 1 또는 Mode 2. 두 모드를 모두 시험했으면 각각 행을 만든다 |
| OS | Windows 판번호와 빌드 |
| 게임 빌드 | 버전과 빌드 입력 지문(`BuildIdentity`) |
| 결과 | 아래 3절 항목별 통과/실패/미시험 |
| 증거 | 화면·로그 파일 이름(개인 보정 원본은 첨부하지 않음) |

## 3. 지원 판정 항목

| 번호 | 항목 | 통과 조건 |
|---|---|---|
| C1 | 장치 열거·선택 | 실제 장치가 목록에 나타나고, 선택한 장치의 실시간 입력 막대가 움직임 |
| C2 | 축 배정·방향 | Roll/Pitch/Yaw/Throttle 네 축을 배정하고 양의 방향이 기체 반응 방향과 일치 |
| C3 | 범위·중립·최저 스로틀 | 전체 범위 수집, 중립이 측정 범위 가운데 60% 안, 반전 후 최저 스로틀 명령 5% 이하 |
| C4 | 검토 저장·재실행 | 저장 → 게임 재실행 → 같은 장치 재연결 시 보정 유지. 다른 장치에는 자동 적용하지 않음 |
| C5 | 아밍 버튼 | 버튼 학습, 토글/2단 스위치, 누른 채 시작·재연결·높은 스로틀에서 예기치 않은 ARM 0회 |
| C6 | 연속 비행 | 이륙 → 호버 → 이동 → 착륙을 실제 스틱으로 수행하고 입력 손실이 0회 |
| C7 | 분리·재연결 | 비행 중 케이블 분리 시 입력 손실로 처리하고, 재연결만으로 모터를 다시 켜지 않음 |
| C8 | 다른 PC | 다른 물리 PC에서 C1~C4를 처음부터 다시 수행 |

C1~C7을 모두 통과해야 **지원**, C1~C4만 통과하면 **부분 지원(비행 미검증)**으로 등록한다. 같은 PC의 새 폴더 시험과 합성 입력 시험은 C6~C8의 근거로 쓰지 않는다.

## 4. 현재 지원 목록

| 장치 | 입력 경로 | Mode | C1 | C2 | C3 | C4 | C5 | C6 | C7 | C8 | 등록 상태 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| RadioMaster Boxer (펌웨어 미기록) | WinMM | Mode 2 | 통과 | 부분 | 통과 | 부분 | 미시험 | 미시험 | 미시험 | 미시험 | **부분 지원 후보 — 비행 미검증** |

Boxer 행의 근거는 AGENTS.md와 [검증 기록](verification.md)의 R5·R6 기록이다. R5는 실제 Boxer로 유휴 입력 거부와 취소를 확인했다. R6은 X/Y/V/Z를 Roll/Pitch/Yaw/Throttle로 배정하고, 정방향, 실제 전체 범위, 중립·최저 스로틀 확인을 저장했다. 저장한 보정을 불러와 모든 기체 DISARM 상태에서 USB를 활성화했다(UI 검사 45개). C2는 축 배정과 정방향 저장까지만 확인했고 실제 기체 반응 방향은 확인하지 않았다. 그래서 `부분`으로 둔다. C4의 재실행 후 같은 장치 재연결 시험은 현장 기록이 없어 `부분`으로 둔다. 연속 USB 비행, 케이블 분리, 아밍 버튼 실물 시험, 다른 PC는 미시험이다. 이 문서 작성 시점에 실물 조종기는 학교에 있어 새 시험을 하지 않았다.

다른 기종은 아직 시험하지 않았으므로 목록에 없다. **"모든 USB 조이스틱 지원"으로 표기하지 않는다.**

## 5. 입력 경로 확대 후보와 선행 조건

| 후보 | 장점 | 먼저 확인할 것 |
|---|---|---|
| Raw Input(HID) | 장치 경로 기반 식별, 축·버튼 수 제한 완화 | 기존 `RadioProfile.json` 보존·변환·취소 시험, WinMM 결과와 같은 장치 비교 |
| DirectInput | 다수 조종기 드라이버 호환 | 축 매핑 차이, 포커스 상실 시 입력 처리 |
| XInput | 게임패드 표준 | 드론 조종기 대부분은 XInput 장치가 아니므로 우선순위 낮음 |

입력 경로를 추가하면 **입력 취득 계층과 보정·비행 계층을 분리**한다. 같은 장치를 WinMM과 새 경로로 각각 시험해 축 순서·범위·중립이 같은지 대조하고, 결과가 다르면 기존 경로를 기본값으로 유지한다. 새 경로를 도입하기 전에 실물 `RadioProfile.json`을 백업하고, 읽기·변환·취소·복구를 따로 시험한다(계획서 4절).

## 6. 상태
