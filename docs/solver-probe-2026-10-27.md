# CTL-13 물리 계산 주기 계측 — 2026-10-27

**카운터 계측과 기존 비행 회귀를 로컬에서 검증했다. 독립 고정120Hz 비행 제어는 아직 미구현이다.**
개발 브랜치는 `codex/r9-solver-probe`, 버전 표시는 `0.7.5-dev`다. 일반 실행용 다운로드는
검증된 v0.7.4-r2를 유지하며 이 계측용 실행 ZIP은 새 공개 릴리스로 올리지 않는다.

## 구현한 범위

`-ImperialSolverProbe`를 명시했을 때만 진단 actor와 Chaos callback을 등록한다.
callback은 적분 전/후의 호출 순서·횟수·간격·스레드 식별자만 출력 버퍼에 기록한다.
기체 UObject·컴포넌트·강체 proxy를 읽거나 PID·힘·배터리 계산을 호출하지 않는다.
완료 출력은 게임 스레드에서 회수하고, 파일 저장도 게임 스레드에서 수행한다.

기본 동기 설정과 시험용 `-ImperialSolverProbeFixed`를 비교한다. 후자는10대 모두
DISARM·자율비행 해제 상태를 매번 확인하며, 실제 solver 고정간격 플래그와 측정 간격을
검사한다. 고정간격 실험에서 기체가 ARM되거나 자율비행을 시작하면 실패한다.
고정간격 옵션은 평상시 실행에 적용되지 않으며 종료 시 이전 설정을 복원한다.

solver 단계마다 `pre_simulate → pre_integrate → post_integrate`가 한 번씩 발생하는지,
적분 최소/최대 간격과 호환되는지, 완료된 간격 합이 실제 solver 시계 변화와 같은지 확인한다.
또한 **게임 경과 시간 = 완료된 solver 시간 + 잔여 시간 변화**를 검사한다.
trace는128개, 전체 출력은16,384개로 제한한다. 표준 계측은5~10초,
전체 비행 비교는 완료 신호를 기다리되45초에서 실패하도록 제한했다.

총24개 계측 조건이 통과했다. 순서·누락·복수 적분 오류는0회,
게임/완료/잔여 시간 장부의 최대 절댓값 오차는 약`1.87e-13초`였다.
`MaxSubstepDeltaTime`과 프레임 간격의 부동소수점 경계 때문에60FPS에서3단계,
120FPS에서2단계로 나뉘는 점도 확인했다. **최대 서브스텝120Hz 설정을 실제 고정120Hz로
표시하면 안 된다.** 이번 관찰만으로 기본 설정을 변경하지 않았다.

콜백이 보고한 간격은 solver advance 간격이다. 적분 hook 한 쌍과 엔진 간격 제한의
호환성을 확인했지만, 내부 적분 함수의 실제 인수를 별도 계측한 센서가 있는 것은 아니다.
fixed120 표의 결과를 제어기·센서·모터가 이미120Hz로 실행된다는 근거로 사용하지 않는다.

## 전체 비행·득점 비교

Editor와 Shipping 각각에서 관찰자를 끈 기준 실행과 켠 실행을 비교했다.
관찰자는 월드 시간 약0.516667초에 등록되어43.016669초의 검사 완료 프레임까지 유지됐고,
7,650개 solver 단계를 관찰했다. 최종 비행 지표를 저장한 후 같은 프레임의
PostPhysics 완료를 기다려 계측 결과를 저장하고 종료한다.

| 실제 회귀 지표 | 기준 실행 / 관찰 실행 |
|---|---:|
|호버 목표 위치 오차|3.150cm / 3.150cm|
|네트 힘 모델 최대 변위|0.06753m / 0.06753m|
|화면용 네트 최대 변위|0.06460m / 0.06460m|

|실제 기체의 골대 통과|청팀1득점·오프사이드 검사 통과|

두 실행의 모든 비교 수치는 유한수인지도 검사한다. 종료 상태가 같다는 결과를 연속 궤적
전체·속도 벡터 전체·전류 시간 적분의 동일성으로 확대하지 않는다. PostIntegrate 계측은
작업자 동기화를 추가하므로 성능 비용이0이라는 뜻도 아니다.

## 자체 검토에서 보완한 부분

- 초기 관찰자가8초에 끝나27~43초의 접촉·득점 구간을 포함하지 못했다. 전체 비행
  완료 신호에 연결하고 실제 시작/종료 시각을 검사하도록 수정했다.
- callback 시간 합과 solver 시계만 비교하던 검사를 게임 시간·시작/끝 잔여 시간까지
  연결했다. 일부 물리 작업이 빠져도 내부 합만 맞아 통과하는 경우를 막는다.
- 잘못된FPS, 단독 passthrough, fixed+passthrough 조합, 고정 계측 중 ARM/자율비행의
  네 조건을 Editor/Shipping에서 각각 거부했다. 오류 이유와 소스 지문도 대조했다.
- UE5.8 Windows의 정상 종료는 실패 요청에서도 프로세스 코드0이 남았다. 첫Tick으로
  옮겨도 동일했다. 엔진 강제 종료로 바꾸지 않고 **명시적 결과 JSON의 실패·이유**를
  판정한다. 성공 시에도 종료 코드만으로 통과시키지 않고 결과 내용을 검사한다.
- Python 최적화로 `assert`가 꺼진 환경은 검사 시작 전에 거부한다. NaN이 집계 함수에
  가려지지 않도록 각 기체의 CSV 비교값을 먼저 검사한다.

## 빌드·압축 해제 검사

Editor/Shipping 빌드가 통과했다. 로컬 계측 ZIP은
`ImperialWings-Windows-v0.7.5-dev-probe-r1.zip`이며374,800,877바이트다.
SHA-256은 `7bbc2a76527ec2a7685e13383c171198c7065e47f06237e32586eb7d047a48be`다.
이는 **로컬 QA 자료이며 공개 다운로드 파일이 아니다.**

새 한글·공백 경로에서13개 배포 검사를 통과했다. 파일 해시·피드백 양식, 개발 도구 없이
실행기 경로 해석, 동봉 APF의10대 응답·제한 시간 종료, 첫 사용자 데이터 경로와 조종기
보정 미생성, 실행 후 패키지 내부에 개인 설정이 생기지 않는 점을 포함한다.
저장된 실제 조종기 보정은 작업 전후 바이트 동일하며 공개 파일에 포함하지 않는다.

소스 내용 지문은 `1a6b144d1404dfc32b5336125d5236f9ad3f97f0ab3019b9378943cd90cf955f`
(125개 입력)다. 빌드 시점의 부모 커밋은`97e88f1`, 수정 표시가true이며 이후 공개 커밋이
그 실행본에 내장됐다고 주장하지 않는다. 게시 소스와 비교할 기준은 정규화한 내용 지문이다.

재실행은 프로젝트 개발 환경에서 아래처럼 한다. 엔진 경로는 설치 위치에 맞춘다.

```powershell
.\.venv\Scripts\python.exe Tests/run-solver-probe.py --engine '<UE 설치 폴더>' --compare-flight
.\.venv\Scripts\python.exe Tests/run-solver-probe.py --packaged --package-root '<압축 해제 폴더>\Windows' --compare-flight
```
